## Context

TestGen 是 Flask 单体应用，API 蓝图包含大量局部 `try/except`，错误体主要使用 `{"error": ...}`，但错误码、内部信息保护和日志行为并不一致。SQLite 初始化依赖 SQLAlchemy `create_all`，现有模型对高频过滤与关联字段没有显式索引，且旧数据库缺少增量建索引路径。应用已有多 Agent 专用健康接口，但没有平台级存活、就绪和轻量运行指标。

本次将三个紧急项保留在同一个 change 中，因为它们都落在 Flask 请求生命周期和数据库初始化边界，能够共享测试基线并统一验证稳定性。实现必须兼容当前原生前端和现有成功响应，不修改测试用例生成业务。

## Goals / Non-Goals

**Goals:**

- 在不破坏现有 `error` 字符串字段的前提下形成统一 API 错误契约。
- 阻止 5xx 响应泄露异常文本，同时保留可关联的服务端异常日志。
- 为已确认的高频过滤、关联和排序查询增加最小必要索引。
- 确保新数据库与已有 SQLite 数据库都能幂等获得索引。
- 提供应用存活、数据库就绪和 JSON 格式轻量运行指标。
- 通过 TDD 覆盖正常、异常、并发安全和升级场景；若测试失败，先审计用例逻辑。

**Non-Goals:**

- 不迁移 SQLite，不引入 Alembic、PostgreSQL、Redis 或任务队列。
- 不部署 Prometheus、Grafana、日志聚合或外部告警系统。
- 不统一重写所有路由的业务异常分支，不改变成功响应。
- 不修改前端框架、RAG、多 Agent 或生成管道行为。

## Decisions

### 1. 使用兼容式错误信封和 Flask 请求生命周期钩子

API 错误体采用 `error`、`code`、`request_id` 和可选 `details`。`error` 继续保持字符串，兼容现有前端；`code` 提供稳定的机器标识；`request_id` 用于关联日志。请求钩子为 `/api` 请求分配或透传合法请求标识，响应钩子补齐现有 4xx 错误体，并把所有 5xx 的客户端消息替换为通用文本。全局异常处理器负责未捕获异常的回滚与带堆栈日志。

选择请求生命周期归一化，而不是一次性改写数十个路由，是为了缩小回归面并立即覆盖现有错误分支。备选方案是引入自定义异常类并逐端点迁移；它长期更严格，但本轮成本和风险过高，可在后续 change 渐进实施。

### 2. 索引由模型声明和幂等迁移共同维护

模型使用 SQLAlchemy `Index` 声明索引，保证新数据库结构正确；数据库初始化阶段调用独立的幂等索引迁移，使用固定白名单和 `CREATE INDEX IF NOT EXISTS` 补齐旧数据库。首批索引围绕实际查询建立：需求创建时间及状态、用例需求关联及需求/状态组合、生成任务需求关联及状态/创建时间组合。

不引入 Alembic，因为项目当前使用内置迁移脚本和启动初始化，单为索引引入新的迁移框架会扩大部署变更。迁移函数保持独立可测，后续可平滑纳入正式迁移体系。

### 3. 基础可观测能力保持无外部依赖

新增平台级存活接口、就绪接口和 JSON 指标接口。存活只证明 Flask 请求循环可响应；就绪执行轻量 `SELECT 1` 检查数据库，失败时返回 503；指标使用进程内、加锁的计数器记录请求总量、错误总量、按状态码计数、累计耗时和进程启动时间。

选择 JSON 指标而不是 Prometheus 客户端，避免本轮增加依赖和部署组件。进程内指标重启后清零且不跨进程聚合，这是基础诊断能力的明确限制。

### 4. 测试边界优先于实现修正

先为错误契约、旧库索引迁移、健康状态和并发计数编写失败测试，再实现最小改动。任何失败先判断测试是否与已确认契约、Flask 生命周期和 SQLite 行为一致；仅在用例逻辑成立后修改生产代码。

## Risks / Trade-offs

- [响应归一化可能影响依赖原始 5xx 文本的调用方] → 保留 `error` 字段类型并明确 5xx 文本属于不稳定内部信息，增加契约测试。
- [响应钩子可能遇到非 JSON 错误响应] → 仅处理 `/api` 且状态码不小于 400 的响应，对无法解析的响应构造标准错误体。
- [索引增加写入成本和数据库体积] → 只覆盖代码中已确认的高频查询，不为低选择性字段单独建立冗余索引。
- [启动时迁移失败影响可用性] → 使用事务和幂等语句，记录明确失败日志；索引异常不修改业务表数据。
- [进程内指标不适合多进程聚合] → 在接口元数据中标明进程级语义，完整监控平台留待后续 change。
- [健康检查自身增加数据库压力] → 就绪查询只执行 `SELECT 1`，不访问业务表。

## Migration Plan

1. 在测试数据库验证模型索引和旧数据库幂等迁移。
2. 部署应用时由现有数据库初始化路径创建缺失索引；所有语句支持重复执行。
3. 注册错误处理与可观测钩子，保持既有 API 路径和成功体不变。
4. 部署后检查存活、就绪、指标接口，并验证典型 4xx/500 响应。
5. 若需回滚，移除请求钩子和新接口；索引可保留且不影响旧代码，必要时再通过显式迁移删除。

## Open Questions

无。本轮接口采用进程级 JSON 指标，完整 Prometheus/Grafana 集成明确留到后续变更。
